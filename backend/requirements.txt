# WHAT THE HQ SERVER NEEDS TO RUN. Nothing else.
#
# This file used to be a freeze of the whole virtual environment - 140 pins,
# including openai, stripe, pandas, motor, boto3, huggingface_hub and the
# google-generativeai stack. Not one of them is imported anywhere in backend/
# or tools/; they are scaffold from the project template that a `pip freeze`
# faithfully wrote down. They cost nothing on this Windows machine, where they
# are already installed, which is exactly why they survived so long.
#
# They stop being free the moment this product is installed somewhere else: a
# fresh machine, a container, a free-tier host with a build timeout and a
# 512 MB memory limit. Then they are hundreds of megabytes and several minutes
# spent installing an LLM client, a dataframe library and two cloud SDKs that
# no line of this codebase calls. Every name below was found by parsing the
# import statements of backend/, tools/ and scripts/ - not by freezing.
#
# THREE FILES, because there are three different machines:
#   requirements.txt           - the HQ server (this file)
#   requirements-receiver.txt  - a Store desktop running the Receiver
#   requirements-dev.txt       - a machine running the tests
# The Store desktop needs no web framework and no database driver; the server
# needs no Windows Core Audio bindings. A host that installs this file gets
# what serves HTTP and WebSockets, and stops there.
#
# Direct dependencies are pinned exactly. Their own dependencies are left to
# pip, which is the difference between "we chose this version" and "this is
# what resolved on the day somebody ran freeze" - the second was how greenlet
# and pycparser ended up looking like decisions.
#
#     python -m pip install -r backend/requirements.txt
#
# PYTHON 3.12. Not a preference - psycopg-binary 3.2.3 publishes no wheel for
# 3.13 or 3.14, so this file does not install at all on a newer interpreter
# (verified: pip offers 3.2.10 and up on 3.14). A deployment image must say
# python:3.12 rather than inherit whatever the host defaults to, which is the
# kind of thing that turns into a build failure on somebody else's machine
# months later. Moving to 3.13+ means moving that pin, deliberately.

# --- the web layer -----------------------------------------------------------
fastapi==0.110.1
# Pinned alongside FastAPI rather than left to it: 0.110.1 accepts a narrow
# range, and Starlette is imported directly here (StaticFiles, WebSocket,
# responses), so it is a dependency of ours and not only of FastAPI's.
starlette==0.37.2
pydantic==2.13.4
uvicorn==0.25.0
# NOT optional, despite looking like it. Plain uvicorn speaks no WebSocket at
# all; it loads this at startup and every Store Receiver's connection rides on
# it. Left out, the console starts, the pages load, and no shop ever connects.
websockets==16.0
# Multipart form parsing - recording uploads and chat attachments.
python-multipart==0.0.32

# --- storage -----------------------------------------------------------------
SQLAlchemy==2.0.51
# PostgreSQL, required in production: APP_ENV=production refuses to start
# without a DATABASE_URL, and SQLite is a development convenience only. See
# backend/db_config.py and docs/SUPABASE_PRODUCTION_CUTOVER.md. The -binary
# distribution is what avoids needing libpq and a compiler on the host.
psycopg==3.2.3
psycopg-binary==3.2.3

# --- identity ----------------------------------------------------------------
PyJWT==2.13.0
bcrypt==4.1.3

# --- everything else the server actually imports -----------------------------
python-dotenv==1.2.2
# Image handling for chat attachments and enrolment artefacts.
pillow==12.3.0
# Process supervision in tools/hq_runtime.py - it owns the uvicorn child.
psutil==7.2.2
